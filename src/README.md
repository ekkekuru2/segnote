# 技術構成について

## ディレクトリ構成

```
├── nextjs
└── worker
```

## 概要

- アプリケーションフレームワークにはnextjsを使う。
    - UIコンポーネントライブラリはshadcn/uiとかにしようかな
        - デフォルトはライトモードで提供。明るい印象にしたい。ダークモードは開発者向けっぽくなってしまってちょっと怖い。ダークモードはオプション。
    - NextJSはデータベースとのCRUDとかをやる
- 機械学習周りはPythonで書く。
    - バックエンドはHTTP APIなど外部との通信を持つわけではない(FastAPIなどは使わない)
    - GPUなどのアクセラレータがあるサーバーの上で常駐しており、データベースにジョブが来たらそれを処理する
    - いい感じに並列にする必要がある。
- データベースはPostgreSQL
    - 範囲型とかあるのが良さそう
- nextjsとPythonで書かれたジョブのワーカーとの連携はPostgreにジョブテーブル的なのを作ってやる
    - Redisとか使う例も出てくるけどとりあえずはそこまでいらないかな

# 仕様

## 各画面について
### / ルート
- サービスについての概要
- 既にログインしている場合は自分が所属しているTeamのうち最後にアクセスしたチームトップ画面に飛ぶ

### /t/[teamId]   チームトップ画面
- 最近の録音がリスト表示されている
- 新しい録音をアップロードできる
    - 音声ファイルもしくは動画ファイルがアップロードできる
    - 現時点では、動画ファイルをアップロードしてもパイプラインでは音声のみ抽出して処理する。各録音の画面で映像と一緒に見れるだけ。将来的には映像に対する解析もできるようにしたい。

### /t/[teamId]/recs/[recordingId]   各録音の画面
- この画面がこのアプリケーションの肝。あとで作る。

- recordingIdは、アップロードされたファイルのメタデータから取得した作成日時と曲名から決定する。
    - 例: 20260727_102539_チャイコフスキー交響曲第5番
    - 曲名は、musicの流さのうち、どのReferenceがヒットしたSegmentが多いかで判定する


## 各録音のパイプライン処理について

1. inaSpeechSegmenterで音声全体をspeech,music,それ以外に分ける
2. 音量調節
    - music区間については、music区間どうしの相対的な音の大きさは変更しないようにしながら、全てのmusic区間のうち一番音量が大きい部分が0dB(音割れしないギリギリ)になるように音量を上げる。(オーケストラなどではダイナミクスも大事)
    - speech区間に対しては、前項のmusicの音量調節をした上で聴く人がなるべく音量調整しなくて良い音量(例えば、music区間をさらに短い0.5秒くらいの等間隔の区間に分けて、(音量*区間幅)/長さ、のように重みつき平均を取るとか？  これが聴覚的に正しいのかは分からない)にノーマライズする。
3. speech区間に対するwhisperによる文字起こし
4. 各music区間を、参考音源の対応する部分と紐付けする
